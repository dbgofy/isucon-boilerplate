# 必要な情報

必要な情報: 対象ポータル URL、認証方法・認証情報の保管場所、必要な CA 証明書と信頼方法。既に提供・許可された内容は再質問しない。秘密情報の値は書かない。

# 目的

競技開始後に使えるポータルへ入れ、ベンチマーク実行と結果確認の場所を確定する。

# 前提条件

- ポータルの URL と認証情報の場所はユーザー提供情報を使う。
- 認証情報はリポジトリに保存しない。
- マニュアル本文の確認は `read-manual.md` で行う。

# 対象サーバー

なし。

# 作業

- URL に加え、必要な CA 証明書の場所・信頼方法、認証方法を確認する。秘密情報の値は記録せず、未承認の証明書検証無効化は行わない。
- 現時点で利用可能なブラウザー専用ツールを確認し、ブラウザー接続の障害とポータルの証明書・通信エラーを区別する。
- ベンチ投入前に到達性と待機中・実行中のジョブを確認する。不通時は採取開始・重複投入を止め、復旧時に既存ジョブを再確認する。hosts 運用では通常 DNS の NXDOMAIN だけで原因を断定しない。
- インスタンス削除・再作成中と分かった場合は retry を止める。接続先を推測した迂回や無関係な runtime 再起動をしない。

- ポータルへログインできることを確認する。
- チーム情報、ベンチマーク実行、結果表示の場所を確認する。
- マニュアルや配布物への導線がある場合は、その場所だけ記録する。
- 不明点を Issue に記録し、推測と確認済みの事実を分ける。

## 実行例

コマンドは実行例である。問題や環境によって構成、パス、サービス名、接続方法は異なる。Issue に記録したユーザー提供情報と実機の状態に合わせて読み替える。

## 1. 参照先を Issue に固定する

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
## 参照

- ポータル URL:
- 認証情報の場所（値は書かない）:
- 確認した時刻:
EOF
)"
```

## 2. 画面で確認し、事実だけ記録する

未確認を確定事項にしない。ログインできない場合は推測で別 URL を使わない。

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
## 確認済みの事実

- ログイン可否:
- チーム情報の表示:
- ベンチマーク実行の場所:
- 結果 / スコアの確認場所:
- マニュアル / 配布物への導線:

## 不明点

- 内容:
- 確認担当:
- 確認方法:
EOF
)"
```

# 確認方法

Issue に参照 URL、確認済みの事実、不明点が分かれて書かれていること。

```bash
gh issue view "$ISSUE"
```

# 失敗時の復旧

- URL や認証情報が分からない: 推測で過去問のポータルを正にしない。ユーザーへ確認する。
- ログインできない: 運営への確認担当を決め、別アカウントや別 URL を推測で試さない。

# 完了条件

- チーム内でポータルの使い方を共有できている。
- 不明点の確認担当と確認方法が決まっている。
