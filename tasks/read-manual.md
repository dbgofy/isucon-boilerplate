# 目的

競技開始後に共有されるマニュアルから、初期化、ベンチマーク実行条件、提出方法を確認する。

# 前提条件

- マニュアルの URL または配布場所はユーザー提供情報を使う。
- ポータル経由で共有される場合は、`check-portal.md` で導線を確認済みであること。
- レギュレーションの確認は `read-regulation.md` で行う。未公開のマニュアルを先取りしない。

# 対象サーバー

なし。

# 作業

- マニュアルを読む。
- ベンチマークの実行条件とスコアの扱いを確認する。
- initialize の要否と提出方法を確認する。
- 不明点を Issue に記録し、推測と確認済みの事実を分ける。

## 実行例

コマンドは実行例である。問題や環境によって構成、パス、サービス名、接続方法は異なる。Issue に記録したユーザー提供情報と実機の状態に合わせて読み替える。

## 1. 参照先を Issue に固定する

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
## 参照

- マニュアル URL / 配布場所:
- 確認した時刻:
EOF
)"
```

## 2. 確認項目を読み、事実だけ記録する

ブラウザまたは配布 PDF で読む。未確認を確定事項にしない。

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
## 確認済みの事実

- 禁止されている変更 / ツール（マニュアル記載分）:
- ベンチマーク実行条件:
- スコアの扱い:
- initialize の要否:
- 提出方法:

## 不明点

- 内容:
- 確認担当:
- 確認方法:
EOF
)"
```

# 確認方法

Issue に参照 URL、確認済みの事実、不明点が分かれて書かれていること。

```bash
gh issue view "$ISSUE"
```

# 失敗時の復旧

- URL や配布場所が分からない: 推測で過去問のマニュアルを正にしない。ユーザーまたはポータルへ確認する。
- 記載がレギュレーションと矛盾する: 両方を引用し、運営への確認担当を決める。

# 完了条件

- チーム内でマニュアル上の制約と提出方法を共有できている。
- 不明点の確認担当と確認方法が決まっている。
