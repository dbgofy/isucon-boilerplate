# 目的

競技前に公開されているレギュレーションから、禁止事項、スコアの扱い、失格条件を確認する。

# 前提条件

- レギュレーションの URL はユーザー提供情報を使う。
- マニュアルは競技開始後に共有されるため、このタスクでは参照しない。

# 対象サーバー

なし。

# 作業

- レギュレーションを読む。
- 禁止されている変更やツールを確認する。
- スコアの扱いと失格条件を確認する。
- 不明点を Issue に記録し、推測と確認済みの事実を分ける。

## 実行例

コマンドは実行例である。問題や環境によって構成、パス、サービス名、接続方法は異なる。Issue に記録したユーザー提供情報と実機の状態に合わせて読み替える。

## 1. 参照先を Issue に固定する

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
## 参照

- レギュレーション URL:
- 確認した時刻:
EOF
)"
```

## 2. 確認項目を読み、事実だけ記録する

ブラウザまたは配布 PDF で読む。未確認を確定事項にしない。マニュアルの内容を先取りしない。

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
## 確認済みの事実

- 禁止されている変更 / ツール:
- スコアの扱い / 失格条件:
- 提出に関する制約（レギュレーション記載分）:

## 不明点

- 内容:
- 確認担当:
- 確認方法:
EOF
)"
```

# 確認方法

Issue に参照 URL、確認済みの事実、不明点が分かれて書かれていること。

```bash
gh issue view "$ISSUE"
```

# 失敗時の復旧

- URL が分からない: 推測で過去問のレギュレーションを正にしない。ユーザーへ確認する。
- 記載が矛盾する: 両方を引用し、運営への確認担当を決める。

# 完了条件

- チーム内でレギュレーション上の制約を共有できている。
- 不明点の確認担当と確認方法が決まっている。
