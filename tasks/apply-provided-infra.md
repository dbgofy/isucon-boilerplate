# 目的

運営がテンプレートや接続手順を提供している場合に、指定どおり適用し、以後の作業で使う接続先を確定する。
提供形態は問題によって異なる（例: CloudFormation）。

# 前提条件

- ポータル、マニュアル、配布物の場所はユーザー提供情報を正とする。
- 認証情報はリポジトリに保存しない。

# 対象サーバー

運営手順が作成または指定する競技サーバー。未提供なら対象なし。

# 作業

- ポータル、マニュアル、配布物にインフラ手順やテンプレート（例: CloudFormation）があるか確認する。
- 提供されていない場合は、その旨を記録して完了する。
- 提供されている場合は、指定された手順でダウンロードし、必要な範囲だけ適用する。
- 適用後の接続先、ロール、注意事項を Issue に記録する。
- 接続先はユーザー提供情報または運営の手順を正とし、推測で決めない。
- 認証情報はリポジトリに保存しない。

## 実行例

コマンドは実行例である。問題や環境によって構成、パス、サービス名、接続方法は異なる。Issue に記録したユーザー提供情報と実機の状態に合わせて読み替える。

## 1. 提供の有無を確認する

ポータルとマニュアルで、CloudFormation / Terraform / 起動スクリプト / IP 一覧の有無を確認する。

```bash
# 配布物を受け取っている場合のみ。パスはユーザー提供情報。
ls -la "$PROVIDED_DIR"
```

## 2. 未提供なら、その旨を記録して完了する

```bash
gh issue comment "$ISSUE" --body "$(cat <<'EOF'
運営提供のインフラ手順・テンプレートは確認した範囲では提供されていない。
以後の接続先はユーザー提供情報を正とする。
EOF
)"
```

## 3. 提供されている場合は、指定された手順だけ実行する

コマンドは運営手順の原文を使う。次は置き場所の例であり、未提供のツールを実行しない。

```bash
# 例: 運営がファイル名と実行方法を指定している場合のみ
# aws cloudformation create-stack --stack-name ... --template-body file://...
# ./bin/setup.sh
```

適用後に次を Issue へ写す。値は画面またはコマンド出力から取る。

```text
- 適用した手順 / テンプレート:
- 作成されたインスタンスまたは IP:
- ロール / セキュリティグループ:
- SSH ユーザー:
- 注意事項:
```

```bash
# 適用結果の確認例。使う API は運営手順に従う。
# aws ec2 describe-instances --filters Name=tag:Name,Values=... --query 'Reservations[].Instances[].[InstanceId,PrivateIpAddress,PublicIpAddress,State.Name]' --output table
```

# 確認方法

- 提供なし: Issue に「未提供・未適用」がある。
- 提供あり: 接続先がユーザー提供情報または運営出力と一致する。

```bash
gh issue view "$ISSUE"
```

# 失敗時の復旧

- 適用に失敗した: 運営手順のロールバックを使う。独自にリソースを消さない。
- 接続先が不明: 推測で IP を決めない。ポータルとユーザーへ確認する。

# 完了条件

- 提供の有無と、適用した場合の対象・結果が記録されている。
- 未適用の理由がある場合は、その理由が明示されている。
